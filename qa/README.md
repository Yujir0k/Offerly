Исполняемые тесты находятся непосредственно в `qa/`: их относительные импорты серверных модулей сохранены. Результаты, скриншоты, фикстуры и превью отделены от тестового кода.

## Быстрые проверки без рабочего сервера

```sh
npm run check:types
npm run check:api
npm run test:regression
npm run test:grade-matrix
node --import tsx qa/assessment-retakes-check.ts
```

Регрессия использует отдельные базы PGlite в памяти. Матрица проверяет успех, провал и timeout на 12 специализациях × 3 уровнях; это синтетическая проверка поведения, не оценка качества найма на реальных людях.

## Проверки с сервером

Обычные HTTP-сценарии запускаются против отдельного локального QA-сервера с отдельной базой, файловым хранилищем и почтовым каталогом. Явно разрешённые пользователем проверки переноса выделены в `vps/` и используют только собственные синтетические аккаунты. Нельзя открывать базу работающего приложения вторым процессом PGlite. Параметры из `.env.local`, токены и cookie не копируются в отчёты.

`current-resume-http.mjs` требует `TEST_BASE_URL` с отдельным портом и `TEST_FIXTURE_FILE` с одноразовым аккаунтом `session-qa-*`; порты 5173/5174 запрещены. `assessment-fixture-route.ts` — тестовая заготовка для изолированной копии, **не маршрут основного приложения**; в production отключена.

Исходные тесты алгоритма запускаются через `scripts/test-assessment.mjs` с `ASSESSMENT_REFERENCE_DIR`, указывающим на полную исходную распаковку с историческими locks. Параллелизм ограничен двумя файлами; `ASSESSMENT_TEST_CONCURRENCY` допускает 1–16. Не пересоздавать эталонные locks ради успешного теста.

Подробные результаты и практические ограничения: [актуальный отчёт](../docs/reports/2026-10-11/security-final.md).
