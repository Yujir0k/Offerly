# Проверки перенесённого приложения

Сценарии проверяют явно разрешённый пользователем Aeza VPS через закрытый SSH-туннель `127.0.0.1:17874`. Headless Chrome использует отдельный локальный HTTPS-прокси на `18443`; его тестовый сертификат не подтверждает публичный TLS домена.

Запускать из корня приложения. Требуются `VPS_QA_PREFIX=vps-qa-YYYYMMDD-N-` и приватный `VPS_QA_DIR` внутри пользовательского кеша Offerly. Каждый запуск создаёт собственные синтетические аккаунты; используйте новый префикс и не копируйте cookie/пароли в репозиторий. В реальном SMTP такие адреса не используются.

Фикстура подтверждает только собственные тестовые email и ускоряет только собственные сроки испытания. Эти действия нельзя выдавать за реальную доставку почты или естественное ожидание полного времени теста. `hide-qa-data` убирает из выдачи только профили/вакансии явно указанного запуска. Удалённые одноразовые ID записываются приватно отдельно, чтобы анонимизация email не искажала контроль исходных данных.

Перед повторным запуском проверьте актуальные SSH-параметры, пути Chrome и фикстур: это операционные сценарии конкретного переноса, не переносимый unit-test runner. После проверки служебные файлы удаляются из контейнера, приватный прокси останавливается; рабочий сервер продолжает работать.

Проверка скорости 11.10 использует публичный HTTPS домена с обычной верификацией сертификата. Для неё требуются `CAPACITY_ALLOW_PRODUCTION=opherly.ru` и абсолютный `CAPACITY_PRIVATE_DIR`, содержащий приватный targets.json с двумя QA-сессиями. Результаты и cookie не публиковать. Короткие ступени чтения не устанавливают общий максимум пользователей для PDF, регистрации и генерации испытаний. Подробные результаты и границы: [отчёт нагрузки](../../docs/reports/2026-10-11/vps-performance.md).

Для повторов на одной закрытой копии можно задать `VPS_QA_ACCOUNT_LABEL` и `VPS_QA_MATRIX_LABEL`; они создают новые аккаунты внутри того же контролируемого префикса. `VPS_QA_CONTAINER` выбирает QA-контейнер; `VPS_QA_BROWSER_ORIGIN`, `VPS_QA_BROWSER_PORT`, `VPS_QA_TUNNEL_PORT` — закрытый браузерный прокси. Фикстуры находятся в `/tmp`, а не в read-only каталоге приложения.

`vps-mail-scenarios.mjs` требует отдельного `MAIL_QA_ALLOW_SEND=yes` и `MAIL_QA_RECIPIENT` на каждый запуск. Ни один частный адрес не задан в коде. Закрытый TLS sink проверяет маршрутизацию и коды без внешних писем; его результаты не доказывают доставляемость реальному провайдеру. Приватный перехват сохранён только в тестовом контейнере после принятия SMTP и никогда не устанавливается в рабочее приложение.
