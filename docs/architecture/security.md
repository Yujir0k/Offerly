# Техническая защита

11.10.2026. Защиты не добавляют новые пользовательские функции.

## Границы доступа

Сессии HttpOnly / SameSite / Secure в HTTPS production, случайные токены в БД только хешами. Пароли scrypt, OTP и reset grant с TTL и ограничениями. Origin проверяется на изменяющих запросах. Компания работает только со своими объектами; контакты — по согласию конкретной участвующей стороне. MCP имеет собственные scopes, срок, шифрование токена и отзыв. Локальный контур ФСП отдельно от настоящего OIDC.

## Запросы и браузер

Тело проверяется по фактически прочитанным байтам до JSON / multipart-парсинга. Ограничены время чтения, глубина и количество узлов JSON; запрещены prototype-ключи. Ошибки не возвращают SQL / стек и не кешируются. В диагностике сервера сохраняется класс ошибки без адресов, кодов и SMTP-текста.

На страницах используется отдельный nonce на каждый ответ и CSP без `unsafe-eval` в production; iframe и object закрыты, политика `connect-src` ограничена своим сайтом. `style-src unsafe-inline` оставлен для текущих React-компонентов. Caddy ставит HSTS, nosniff, X-Frame-Options, ограничивает размеры тела / заголовков и время чтения. Внешний адрес клиента заменяется собственным прокси, прежде чем приложение использует его для лимитов.

## Файлы и ресурсы

Аватар / медиа действительно декодируются, нормализуются в WebP, очищаются от метаданных; ограничены пиксели, время и число загрузок. SVG и повреждённые / анимированные файлы не проходят как аватар. Приватный ключ файла должен иметь точный префикс владельца. Заменяемый файл удаляется после успешного сохранения новой ссылки.

PDF обрабатывается в отдельном worker: максимум два одновременно, время 20 секунд, отдельный предел JS heap, ограничения страниц / текста / картинок. Эти лимиты JS не покрывают все native buffers; общий предел контейнера остаётся дополнительным барьером.

Большие программы испытаний допускаются по два одновременно; ожидание ограничено 16 запросами и 15 секундами. Резервные наборы генератора имеют LRU на два сочетания track / grade. Содержимое повторной генерации совпадает; математика оценки не изменена. История завершённых попыток читает компактные серверные публичные проекции; приватные снимки не раскрываются и не переоцениваются.

## Эксплуатация

На VPS две одинаковые копии app за Caddy с health checks. Общие БД и uploads, SQL-lock / CAS и transactional outbox обеспечивают общую согласованность. Прокси повторяет GET при недоступном upstream; POST после передачи не переотправляется автоматически. Это устойчивость к перезапуску одного app, а не резервный второй VPS.

Контейнер — пользователь `node`, read-only rootfs, cap_drop ALL, no-new-privileges, предел памяти / PID, ограниченные tmpfs. В БД приложение использует `offerly_runtime`: DML без создания ролей / таблиц и чтения файлов ОС; администратор нужен только миграциям. PostgreSQL наружу не публикуется. На VPS включены firewall и Fail2ban, вход SSH по ключу, password authentication выключена. Секреты находятся вне Git / образа.

## Оставшиеся границы

`npm audit --omit=dev` не показывает уязвимостей на момент проверки. В полном audit остаётся advisory `braces` в цепочке dev lint; исправленного совместимого upstream-релиза нет. Удалённый пользователь не управляет glob-шаблонами ESLint; это не runtime-зависимость. Не применяем ломающий downgrade ради нулевого числа в отчёте.

Эти проверки не заменяют независимый pentest, защиту провайдера от DDoS, внешний мониторинг и регулярные внешние резервные копии. Документы и сроки оператора персональных данных требуют отдельного утверждения.

Источники зависимостей: [Next.js advisory](https://github.com/advisories/GHSA-vcvr-r3jv-pc5j), [dev braces advisory](https://github.com/advisories/GHSA-vfj7-8cjw-p6xm). Настройка CSP: [Next.js](https://nextjs.org/docs/app/guides/content-security-policy).
