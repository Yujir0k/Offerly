# Финальная проверка безопасности и VPS — 11.10.2026

Актуальный релиз `20261011-security-r12`, сайт https://opherly.ru. Проверки выполнены без пользовательской демонстрации. Полные функциональные прогоны использовали отдельную копию PostgreSQL и собственные синтетические аккаунты; рабочие аккаунты и база не сбрасывались. Свежая сборка установлена на VPS, миграция 024 применена, health / HTTPS проверены.

## Что исправлено

- Обновлены Next.js / Sharp и совместимые зависимости; production audit — 0 уязвимостей.
- Origin / CSRF, фактические byte limits до парсинга, ограниченная сложность JSON, безопасные ошибки и private no-store.
- CSP с nonce, браузерные защитные заголовки и ограничения Caddy. Проверена загрузка настоящих форм и блокировка внедрённого parser-inserted script. Фото PDF переносится без ослабления connect-src.
- Контейнер без root / дополнительных capabilities, read-only исполняемые файлы, лимиты PID / памяти / tmpfs. SSH по ключу, firewall / Fail2ban. DB-роль приложения отделена от мигратора.
- Файлы декодируются и нормализуются, owner-prefix проверяется точно; заменённые файлы очищаются после сохранения. PDF изолирован в worker с лимитами.
- Обнаружен и исправлен рост памяти резервного кеша генератора: максимум два LRU-набора. Хеш JSON после вытеснения совпадает. Оценка, seed, методика и исходный архив не изменены. История использует компактную серверную проекцию завершённых отчётов; тяжёлые операции ограничены по параллельности и ожиданию.
- SMTP имеет один повтор только при отказе соединения до передачи письма; после DATA / AUTH повторов нет. Персональный тестовый адрес из публикуемых файлов удалён; общей переадресации нет.

## Почта

Порты Aeza открыты. TLS и авторизация Postbox повторно проверены из рабочего контейнера. Ранее Яндекс принял реальные письма с кодами с VPS, получатель подтвердил получение. Полный внешний прогон остановлен по просьбе получателя; не заявляем заново выполненную доставку всех восьми типов во внешние входящие.

В финальном закрытом TLS SMTP-контуре прошли 68 проверок / 8 писем: регистрация обеих ролей, смена адреса через старый адрес и пароль, recovery, уведомление о смене пароля, приглашение. Коды подошли к соответствующим операциям, неверные коды отклонены. Этот контур ничего не отправляет наружу и не доказывает внешний inbox placement.

Рабочий SMTP настроен. Обновление 11.10 около 11:20 МСК: официальная страница Яндекса показывает Postbox Unavailable; две редкие пробные отправки отклонены кодом 454 Maximum sending rate exceeded до передачи тела. Новые тестовые письма не доставлены. Пользователь попросил выбрать замену провайдера; этот внешний этап остаётся незавершённым. Получатель — адрес соответствующего аккаунта / этапа смены почты, а не адрес разработчика. Отправитель `Офферли <noreply@opherly.ru>`. Postbox не создаёт входящий почтовый ящик.

На последней проверке авторитетный DNS Рег.ру возвращал NXDOMAIN для `_dmarc.opherly.ru`; SPF в TXT корня также не обнаружена. При подключении выбранного нового провайдера следует применить его конкретные SPF / DKIM-записи, не создавать дубликаты SPF, добавить DMARC и проверить заголовки нового письма. Сейчас почтовые DNS не меняются: пользователь отложил этот этап. Начальная политика DMARC `p=none` позволяет наблюдать, но не запрещает подделки; ужесточение требует проверки всех источников отправки. Попадание во входящие не гарантируется одним DNS или оформлением.

## Сверка с ТЗ и оставшиеся действия

Обязательный функциональный путь MVP реализован и технически проверен: профиль вручную / текстовый PDF, специализация / грейд / тест, категория и история, поиск / приглашение с зарплатой, контакты по согласию. Отдельный повторяющийся опрос объединён с выбором профиля по согласованному решению пользователя. Отсутствие соревнований ФСП не выдаётся за достижение; настоящий API организатором не предоставлен, ТЗ допускает собственные тестовые данные.

До массовой работы: регулярные внешние резервные копии и мониторинг / оповещения, утверждённые документы и сроки оператора персональных данных, независимый человеческий пилот методики и отдельный pentest. Ручные резервные копии / восстановление проверялись, но это не ежедневная внешняя резервная система.

Для финальной сдачи ТЗ ещё подготовить презентацию и сопровождающий документ DOC / PDF; в README оставлено место для будущего скринкаста. Код, архитектура, инструкции и скриншоты подготовлены к GitVerse.

Дополнительные функции, которые отсутствуют: автоматические регулярные короткие задачи, OCR сканов, отдельные технологические испытания, полноценные ATS-коннекторы и административная модерация. ТЗ прямо делает регулярные задачи / отклики / адаптивность необязательными для MVP; отклики и адаптивность уже работают. Для антифрода / ATS подготовлена архитектурная концепция. Реальный ФСП / OIDC требует контракта организатора.

Полный npm audit содержит dev-only advisory `braces` в lint-цепочке; исправленного совместимого upstream-релиза нет. В production-зависимостях он отсутствует; ввод пользователя не поступает в glob-шаблоны lint. Проверки не являются гарантией отсутствия всех уязвимостей.

Дополнительный `npm run lint` пока не проходит: 194 ошибки и 165 предупреждений в собственных исходниках и QA. Основные группы — явный `any` и правила React для состояния в эффектах / ref; успешные TypeScript, сборка и функциональные тесты не устраняют этот технический долг. Генерируемые файлы и сторонний vendor исключены из lint; правила собственного приложения не отключались. Массовый рефакторинг этих мест требует отдельной регрессии и новой выкладки, поэтому не выдаётся за уже выполненное исправление.

## Нагрузка и сохранность

Финальный публичный HTTPS-прогон: 50 / 100 / 200 виртуальных клиентов, по 20 секунд, пауза 1 секунда после ответа. Всего 4616 запросов, ошибок 0. Общий p95: 317 / 469 / 1742 мс; при 100 клиентах p95 поиска кандидатов 533 мс, вакансий 417 мс. При 200 p95 поиска 1811 / 1328 мс — этот уровень уже даёт заметную задержку. Это два собственных QA-аккаунта, а не 200 разных людей, и только чтение. Практический вывод: десятки пользователей укладываются в ориентир MVP; нельзя обещать 200 одновременных тяжёлых испытаний / PDF или абсолютный максимум сервера.

Две копии приложения имеют одинаковый образ, PostgreSQL и файловый том. Сеансы и выбранные данные аккаунтов сохранились после последовательной выкладки и через несколько часов. Контейнеры healthy. Полные ответы 40 каталогов до / после сокращения загрузки обзорных данных совпали по SHA-256; браузерные проверки обоих каталогов / отмены старого поиска / desktop и mobile прошли.

Новый dump сохранён вне VPS; SHA-256 совпал. Восстановление в независимый PostgreSQL проверено по 41 таблице: 40 точных совпадений, различается только обновляемая таблица sessions. Рабочая база не заменялась. Для постоянной эксплуатации ещё нужна регулярная внешняя система копий.

Неудачный двухпроцессный замер с паузой локального компьютера отброшен; запросы с тысячесекундным разрывом не являются измерением стабильной нагрузки. Короткий read-only benchmark не является абсолютным максимумом людей для PDF, регистрации и испытаний.

## Переносимость и текущие ограничения

Канонический checkout — эта Git-копия. Старые миграции Drizzle и Cloudflare-примеры исключены; действующие миграции находятся в `db/migrations`. Prehooks собирают vendor перед проверками. Production-сборка использует `tsconfig.build.json` с проверкой всех runtime-файлов; `ignoreBuildErrors` не включён. Повторные `npm ci` и production build прошли с собственной физической установкой зависимостей, без ссылки на прежний кеш. Локальный сервер 5174 восстановлен с прежней базой и файлами. Данные, env, ключи и дампы не входят в Git.

На последней административной проверке SSH Aeza открывал TCP, но не выдавал banner. HTTPS /api/health отвечал200. Код и две копии приложения уже установлены; затруднение SSH не означает падение сайта. Финальная очистка приватного restore-контейнера и дополнительный эксплуатационный restart будут выполнены после восстановления административного доступа.
