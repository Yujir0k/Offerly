# Регистрация и редактирование ответов — 10.10.2026

## Поведение

- Подтверждение почты берётся из аккаунта, а не из контактной почты профиля или компании. Сохранение анкеты не отменяет подтверждение входа.
- После анкеты подтверждённый аккаунт автоматически проходит короткую анимацию и открывает профиль соискателя или компанию работодателя. Повторный вход и кнопка «Продолжить» не нужны.
- Если анкету заполнили до подтверждения, сначала открывается ввод кода; после успешного кода — тот же автоматический переход. Пропуск шагов поддерживает обе роли.
- Правая панель испытания имеет естественную высоту и прокручивается вместе со страницей. В высоком блоке время закрепляется при прокрутке; отдельной внутренней прокрутки нет.
- Длинные варианты и выбранные значения переносятся по строкам. Изменения компонента выбора включаются только для соответствующих полей испытания.
- До завершения можно открыть сохранённый ответ и нажать «Изменить ответ». До подтверждения изменения это только просмотр, прогресс и оценка не меняются.
- После подтверждения ответ снимается с сохранения, прогресс уменьшается. Повторное сохранение увеличивает его без повторного учёта прежних баллов.
- Пока основная выдача находится на независимых начальных сценариях, снимается только выбранный сценарий. При возврате к более раннему этапу снимается выбранный ответ и все последующие ответы; дополнительные кейсы выбираются заново исходным алгоритмом. Число снимаемых шагов показывается до действия. Это консервативное правило предотвращает сохранение решений, зависевших от прежнего состояния.
- Дедлайн, уже просмотренные материалы, история экспозиций, затраченное время и конфигурация оценки сохраняются. Завершённый результат изменять нельзя.
- Итог оформлен как отдельный отчёт: решение по заявленному уровню, четыре стороны компетенции, объяснение, содержание проверки, дата и версии метода. Это публичный отчёт исходного алгоритма, без скрытых ключей.

## Техническая реализация

`lib/registration-flow.ts` определяет переход после анкеты. Клиент использует актуальное состояние, возвращённое сервером; сервер повторно читает подтверждение аккаунта после сохранения.

`lib/professional-navigation.ts` хранит позицию просмотра отдельно от позиции выполнения и реализует снятие ответов. `lib/professional-assessment.ts` подключает операцию `revise`, проверку владельца и ревизию взаимодействия для защиты от устаревших запросов. Аудит снятых ответов хранится только на сервере. Новые необязательные поля находятся в существующем JSON-снимке сессии; SQL-миграция не нужна.

Публичный ответ содержит только текущий сохранённый выбор/план, доступную навигацию, номер ревизии и число снимаемых шагов. Генератор, рубрики, ground truth и вклад в оценку клиенту не выдаются. Повтор идентичного ответа идемпотентен; другой устаревший ответ отклоняется.

Исходники `vendor/fsp-assessment` не менялись. Метод formal-generator-7.3.3, scoring competency-4, веса и пороги сохранены. calibratedForms по умолчанию выключен; ограничение 90 дней не добавлялось.

## Выполненные проверки

- `qa/assessment-revision-check.ts`: 756 проверок, все 12 специализаций × Junior/Middle/Senior. Просмотр, снятие, повторное сохранение, связанные шаги, доказательства, дедлайн, закрытая попытка, соответствие исходному решению и вкладам при одинаковых итоговых ответах.
- `qa/assessment-navigation-check.ts`: 1332 проверки навигации по тем же 36 сочетаниям.
- `qa/assessment-revision-http.mjs`: 50 проверок реального API на отдельной локальной базе. Чужая попытка — 404, роль работодателя — 403, устаревшее изменение — 409; история и замороженный результат сохраняются. Проверено отсутствие закрытых полей в публичном ответе.
- Дополнительно 8 проверок идентичной повторной отправки со старой ревизией: прогресс, дедлайн, ответы и вклад в баллы неизменны; другой ответ отклоняется.
- В браузере: изменение 9% → 0% → 9%, сохранение выбранного варианта после перезагрузки, перенос длинных значений, отсутствие внутренней прокрутки панели, итоговый отчёт на 1280 и 390 пикселях без горизонтального переполнения.
- Регистрация: почта сначала → полная анкета → автоматическое открытие профиля для соискателя и компании для работодателя; анкета/пропуск до кода → подтверждение → тот же переход. Проверена отдельная контактная почта и телефон работодателя. Вход уже подтверждённого аккаунта не требует повторного кода. Дополнительно 21 проверка API регистрации.
- Финальная production-сборка и TypeScript выполняются в чистой копии проекта, без диагностического API и старых сгенерированных файлов локального dev-сервера.

Диагностический `qa/assessment-fixture-route.ts` применялся только в изолированной копии с синтетическими пользователями. Он не установлен в маршруты основного сайта и удалён перед production-сборкой. Настоящие пользовательские данные не удалялись. SMTP и размещение на VPS в эту правку не входят.
