## Что действительно осталось

- Решить вопрос интервала смены грейда: сейчас это осознанное расхождение с исходным ТЗ по прежнему исключению пользователя.
- При получении доступа подключить реальный ФСП ID и достижения; подтвердить у организаторов, не появилось ли окончательное дополнение про общий стенд. По имеющимся материалам обязательного действующего API нет.
- На выбранной инфраструктуре проверить PostgreSQL, приватные файлы, резервное копирование/восстановление, HTTPS, SMTP, контейнер и одновременные генерации. Прежний локальный прогон 50 аккаунтов / 150 чтений `/api/state` не является доказательством производительности тестирования на VPS. Генерация CPU-bound и выполняется в серверном процессе; для заметного роста нагрузки потребуется изоляция workers/сервиса после измерений.
- Перед реальными пользователями утвердить оператора/политику данных и провести человеческий пилот. Синтетическая валидация допустима для хакатона, но не доказывает реальную точность или удобство каждого задания.
- OCR сканов, внешние ATS-коннекторы, модерация/админка, push при закрытом приложении и файлы/звонки в чате остаются развитием продукта, а не заявленными готовыми возможностями этого MVP.

Документы сдачи, публикация репозитория/сервера и сборка обновлённого ZIP здесь не выполнялись. Старый ZIP остаётся историческим; текущие исходники и этот отчёт актуальнее него. Нельзя утверждать «всё ТЗ на 100% и ошибок больше нет»; основной локальный сценарий реализован и прошёл перечисленные проверки.

## Уточнение после аудита: демореестр и интервалы

По следующему запросу пользователя расширен фиксированный реестр ФСП: с историей / без истории / неизвестный ID; исходные реальные аккаунты демоданными не заполняются. Добавлены интерфейс адаптера, ручки собственной истории, дата/источник, показ достижений работодателю. Подробности [fsp-id.md](../../guides/fsp-id.md). Live контракт по-прежнему не предоставлен, его транспорт не заявлен готовым.

21 HTTP-проверка новой истории прошла: own-only, запрет обычному аккаунту, Origin, неверные тела, сохранность при неизвестном ID, очистка, прежний action, неизменность грейда/оценки/verified. Проверка бонуса без достижений прошла. UI обеих ролей, смена сценария и reload прошли; консоль без ошибок. Source TypeScript и production build в чистой копии прошли. Обычная сборка основной папки снова встретила дубли generated `routes.d 2.ts` в `.next-dev`; файлы приложения не являются причиной этого сбоя, кеш работающего сайта не удалялся. Логи и снимки: `qa/2026-10-10-fsp-history/`.

Лимит по-прежнему отсутствует в runtime, как запрошено для текущего тестирования. Рекомендация 90 дней между изменениями подтверждённого грейда / 7 дней после неудачи того же уровня, а также разграничение нагрузки/человеческого пилота записаны в [capacity-and-retakes.md](../../architecture/capacity-and-retakes.md). Это предложение для будущего включения, не уже действующая политика. Изоляция CPU генератора в worker pool пока только архитектурный следующий шаг.
