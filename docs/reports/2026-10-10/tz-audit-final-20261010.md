# Подробная сверка ТЗ — финальный локальный прогон 10.10.2026

Основа: полный исходный `../ФСП спец. трек ТЗ.md` (разделы 1–6), уточнения `../research/14-organizer-qa.md`, текущие исходники, сохранённые результаты и целевые проверки. Исходное ТЗ, исследования, locks и версии доказательств не изменены. Это техническая сверка текущего локального MVP; она не удостоверяет отсутствие всех ошибок или готовность ещё не выбранной инфраструктуры.

Последние решения пользователя: отдельный «Опрос» объединён с выбором направления/уровня; «Проверка уровня» работает, «Проверка навыков» для отдельных технологий честно помечена как разработка. Процессы/этапы найма, встречи и заметки удалены из меню; их исторический backend не заявляется доступной функцией. Ограничения повторов теперь **включены**. Единственный рабочий сервер — `localhost:5174`.

## Что проверено свежим прогоном

Числа — утверждения автоматических проверок, не люди и не процент покрытия. Журналы текущего прогона: `qa/2026-10-10-final-audit/`.

- **44 исходных теста** domain/engineering/session/persistence/express/API/competency-validation — успешно, с исходными сохранёнными locks.
- **1332 проверки** навигации/оценивания на 12 × 3; **36/36 разных наборов публичного содержимого** при одинаковом seed. В digest исключены идентификаторы: различаются задания/контекст/артефакты/ответные поля, а не только ID.
- В матрице проверены formal-generator-7.3.3, competency-4 и исходный серверный срок 20 минут. Старое внутреннее поле assessmentVersion не подменяет актуальную версию generatorVersion.
- **18** границ политики повторов + **12** транзакционных: точная граница 90/7, ниже после неудачи, другое направление, параллельный старт, timeout commit при отказе, неизменность исторического тела.
- **37 HTTP** при внедрении повторов: запреты всех Backend-грейдов после подтверждения, история без новой записи, роли/anonymous/неверные параметры, конкурентный старт одной сессии, снимок версии политики.
- **169 HTTP** по общему рынку: все 36 фильтров, приватность контактов, пагинация и повторы сообщений, общий каталог обычного нового работодателя. После объединения он видит 82 подходящих профиля без фильтров, включая 72 явно условных.
- **17 после повторного перезапуска**: существующие аккаунты обеих ролей, профиль/компания, подтверждённый отчёт, прежний диалог, каталог, ограничение и заполненный демо-отклик.
- **8 проверок обработки загрузки кабинета**: один повтор GET при 5xx, без повторов 401 и POST, отмена запроса, понятная ошибка вместо HTML/JSON parser. Временный 500 при dev-пересборке обнаружен в браузере, кабинет восстановлен.
- **8 изолированных** по выключению условного каталога без удаления записей; проверен поиск, превью, счётчик и обратное включение.
- Повторная проверка FSP-ranking без бонуса за пустой ID и 52 проверки defaults/миграции выполнены при текущих изменениях каталога.
- Браузер: карточки/сохранение слева и действия справа, детали, заполненный отклик/нижний чат, короткая и длинная переписка/прокрутка, крупные аватары, демовход обеих ролей, обычный вход, точная дата ограничения после reload и доступ к старому результату.
- Шапка профиля на фактическом viewport 1280 px: обе кнопки внутри шапки, горизонтального переполнения нет. Повторное управление viewport в текущей сессии браузера не изменило фактическую ширину; поэтому новый полный прогон всех размеров не заявляется. Предыдущие мобильные проверки сохранены, финальная регрессия мобильных размеров после последних правок остаётся ограничением этого UI-прогона.
- OpenAPI: 31 путь, 169 разрешённых ссылок, одинаковые копии; генератор спецификации сохраняет новую политику/429. 111 исходников vendor совпадают с оригиналом побайтно. В 50 клиентских чанках проверенные приватные маркеры ключей/планов/ground truth не найдены.
- Финальная чистая production-сборка включает TypeScript текущих исходников и QA. Проверка основного работающего dev-кеша не подменяет её; кеш пользователя не удалялся.

Ранние полные сквозные прогоны регистрации обеих ролей, 609 найм/грейд/чат, 76 границ чата, 57 auth-lifecycle, 36 автоматической почты, 15 сохранения подсказок, PDF-бенчмарк и 756 изменения ответов сохранены в соответствующих документах QA. Они **не называются заново выполненными целиком этим финальным прогоном**. Сценарий публикация → поиск → приглашение → принятие → контакт → чат → самостоятельный отклик в том же диалоге ранее пройден видимо в браузере; текущий прогон дополнительно проверяет сохранность и регрессии затронутых частей.

## Воспроизведение целевых проверок

Из `offerly-web` после `npm ci` / `npm run assessment:build`:

```sh
npm run test:assessment -- domain.test.js engineering.test.js session.test.js persistence.test.js express.test.js api.test.js competency-validation.test.js
node --import tsx qa/assessment-navigation-check.ts
node qa/assessment-content-matrix.mjs
node --import tsx qa/assessment-retakes-check.ts
PGLITE_PATH=/tmp/offerly-retakes-new ENABLE_DEMO_DATA=false node --import ./qa/server-only-loader.mjs --import tsx qa/assessment-retakes-server-check.ts
PGLITE_PATH=/tmp/offerly-showcase-policy-new ENABLE_DEMO_DATA=true node --import ./qa/server-only-loader.mjs --import tsx qa/showcase-policy-check.ts
npm run build
```

Каждому DB-прогону дать **новую пустую временную папку**, не `.data/postgres` работающего сайта. `DATABASE_URL` должен быть unset для изолированных прогонов; скрипты это проверяют. Для исходных тестов нужен полный original archive root через `ASSESSMENT_REFERENCE_DIR`, если он не лежит по указанному относительному адресу. Исторические locks не регенерировать. Тяжёлые калибровочные исследования не запускаются ради UI-интеграции.

## Доказательства качества и оставшиеся границы

Основной holdout 7.3.3: Junior 95,69%, Middle 85,14%, Senior 83,33%; финальная серия — **201600 синтетических запусков**. 36 ручных AI-прохождений относятся к 7.2.6; 24 задачи переходов и большие аудиты инвариантности — к 7.3.2. Серии с `PROTOCOL_DEVIATION.json` не считаются свежим holdout. Автовыбор трёх форм calibratedForms по умолчанию выключен. Пороги, веса 1/1,5/2, priors, формальные правила и locks не менялись.

Для локального обязательного функционала по этому аудиту не найден незакрытый пункт, кроме зависимых от эксплуатации подтверждений. До публичной работы остаются: выбранный VPS/PostgreSQL/приватные файлы/HTTPS, реальная почта, проверка восстановления резервной копии и нагрузки именно там, окончательные настройки хранения/оператора данных. Реальный ФСП/OIDC/реестр подключается при появлении контракта; для текущего ТЗ работает допустимая маркированная имитация. Человеческий пилот нужен для проверки пригодности грейдов и понятности, синтетика его не заменяет.

Регулярные задачи, OCR сканов, ATS-коннекторы, административная модерация, вложения/звонки и фоновые push — отсутствующие дополнительные функции, не скрытые обязательные пункты MVP. Административного UI отмены ошибочно израсходованной попытки пока нет. Производительность не гарантируется одной лишь архитектурой: синхронный генератор — известная граница; worker pool/отдельный сервис рассматривается по замерам, не объявлен реализованным.

Исходный архив, распаковка, калибровка и первичная валидация сохранены. Старый переносимый ZIP исторический и не содержит всех последующих правок; актуальны текущие исходники. Новые материалы сдачи/публикация на сервер здесь не выполнялись.

При проверке сначала выявлены ошибки TypeScript в новых QA-файлах (nullable результат/пропущенный аргумент поиска) и некорректное закрытие тестового DB-wrapper. Они исправлены; неуспешные промежуточные запуски не считаются прохождением. Финальные журналы сохраняют только результаты исправленного прогона.
