# Минимальные резервные копии MVP

Настроено 11.10.2026 без стороннего хранилища и платных услуг. Обновления ОС, перезагрузки и перезапуски приложения по просьбе владельца не выполнялись. SSH восстановлен: существующий ключ работает; соединению мешал маршрут VPN. Только для этого VPS в локальном SSH config выбран интерфейс en0. При смене сетевого интерфейса эту настройку нужно пересмотреть.

## Расписание и хранение

- VPS: по средам и воскресеньям в 03:00 UTC / 06:00 МСК через уже работающий cron. Последние три завершённые копии в `/opt/offerly/backups/automatic`.
- Автоматическое копирование на Mac отменено пользователем; созданный LaunchAgent удалён, две новые локальные копии удалены.
- Текущий архив около 77 МБ; три копии займут примерно 230 МБ при текущем размере данных. Размер растёт вместе с данными. Прежние ручные архивы за пределами managed-каталога эта ротация не удаляет.

Копии на том же VPS помогают восстановиться после ошибки приложения или изменения данных. Потеря самого VPS/диска уничтожит и эти копии; отдельное внешнее хранилище сейчас не подключено по решению владельца. Между запусками копирования могут пройти до четырёх дней.

Снимок содержит PostgreSQL custom dump, uploads, приватное окружение, конфигурации Compose/Caddy, метаданные релиза и SHA256 файлов. Каталоги имеют права 700, архивы 600. Шифрование диска VPS отдельно не подтверждено. Архивы содержат секреты и персональные данные: не публиковать их в Git и не отправлять публично.

## Ограничение нагрузки

`deploy/backup-minimal.sh` использует горячий `pg_dump`, без остановки БД. Два прохода rsync охватывают файлы до и после снимка БД; старые файлы в промежуточной копии не удаляются. Это не атомарный снимок БД и файлов в единую наносекунду при одновременном удалении/создании файлов.

Запуск через cron имеет CPU nice 19, дисковый idle-приоритет и предел времени 300 секунд; dump — 120 секунд и ожидание блокировки до 5 секунд. Параллельный запуск исключён flock. При недостатке свободного места для промежуточной копии и архива плюс резерва 10 GiB либо доступной RAM менее 512 MiB копирование пропускается. Эти ограничения уменьшают влияние, но не гарантируют нулевую нагрузку.

Завершённая копия публикуется только после dump/проверки списка восстановления и создания SHA256. Ротация затрагивает только собственные файлы в managed-каталоге; прежние ручные копии сохраняются. Журнал `/var/log/offerly-backup.log` ротируется еженедельно, четыре архива. Автоматические оповещения не подключены.

## Установка на такой же VPS

Сначала проверить имена контейнера, роли БД, volumes и расположение приватного env. Значения по умолчанию заданы в скрипте; можно переопределить переменными `OFFERLY_*` из его начала. Скрипт предназначен для Linux с Docker, rsync, flock, timeout, nice, ionice, tar и gzip. Не устанавливает пакеты и не перезапускает службы.

Установить скрипт как `/usr/local/sbin/offerly-backup` с правами 750, cron-файл из `deploy/offerly-backup.cron` как `/etc/cron.d/offerly-backup` с правами 644, конфигурацию ротации из `deploy/offerly-backup.logrotate` как `/etc/logrotate.d/offerly-backup` с правами 644. Создать журнал с правами 600. В cron-файле указано расписание для UTC; проверить часовой пояс сервера.

Ручная копия и проверка архива на VPS:

```sh
sudo nice -n 19 ionice -c 3 timeout 300 /usr/local/sbin/offerly-backup
sudo /usr/local/sbin/offerly-backup --latest
# В приватном каталоге копий, подставив фактическое имя:
sha256sum -c YYYYMMDDTHHMMSSZ.tgz.sha256
```

## Проверка и восстановление

Проверить SHA256 архива, распаковать в приватный каталог, выполнить `sha256sum -c uploads.sha256` из него. Создать **отдельную пустую тестовую БД**, затем выполнить `pg_restore --exit-on-error --no-owner --no-acl -d ИМЯ_ТЕСТОВОЙ_БД database.dump`. Сверить таблицы, ключевые количества и ссылки на файлы. Не восстанавливать поверх рабочей БД в качестве проверки.

Фактическое аварийное переключение на восстановленную БД/файлы требует отдельного согласованного окна; текущая настройка его не выполняет. Конфигурации с секретами восстанавливать с правами 600. Метаданные указывают исходный релиз и образ; исходники опубликованы отдельно в GitVerse.
