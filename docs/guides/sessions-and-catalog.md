# Устройства и каталоги

## Устройства и сеансы

Отдельный пункт настроек в обеих ролях. Показывает браузер/систему, текущий сеанс, вход и последнюю активность в выбранном часовом поясе. Можно выйти с этого устройства, завершить отдельный чужой сеанс своего аккаунта или все остальные. Действия подтверждаются минимальным фирменным диалогом; удаление аккаунта остаётся отдельным пунктом настроек.

`GET /api/sessions` возвращает только активные сеансы текущего пользователя. Публичный UUID отличается от хеша токена. Cookie/токен/хеш/IP/User-Agent не передаются клиенту. Название приблизительное, из ограниченного User-Agent; старые сеансы без метаданных обозначены «Неизвестное устройство». Последняя активность обновляется не чаще раза в 5 минут. TTL остаётся 14 дней. Миграция 006 сохраняет существующие входы.

`POST /api/sessions` с Origin и JSON:

- `{action:"revoke", id:"…"}` — завершить другой собственный сеанс; чужой/уже закрытый ID ничего не меняет.
- `{action:"others"}` — завершить все остальные, сохранить текущий.
- `{action:"logout"}` — завершить текущий и удалить cookie.

Отозванный сеанс сразу перестаёт проходить серверную авторизацию. Открытый кабинет узнаёт об этом на следующем запросе, фокусе окна или периодической проверке (15 секунд при активной вкладке) и возвращает ко входу. Это сеансы Офферли; глобальный выход из Keycloak пока не подключён.

## Каталоги

`GET /api/catalog/jobs` и `/api/catalog/candidates` принимают `filters` (JSON существующих VacancyFilters/CandidateFilters), `page` (от 1), `role`. Вакансии работодателя также принимают `scope=market|published|draft|archived`. Размер страницы фиксирован — **20**, клиент не может увеличить LIMIT. Ответ: `{items,total,page,pageSize}`. Страница за концом выдачи ограничивается последней. Сортировка имеет стабильный вторичный ID; фильтры выполняются до LIMIT/OFFSET. Числовой запрос кандидата означает точный ID.

Сохранены специализация/грейд, все выбранные навыки (И), отрасли/форматы, пересечение зарплат, опыт/локация, компании и их исключение, избранное, история ФСП, сортировки. Фильтр «свежие» использует предпочтения профиля и исключает уже отправленные отклики. Кандидатам недоступны чужие черновики; работодатель видит только свои черновики/архив. Архивная вакансия остаётся доступной кандидату через собственный отклик. Демо изолировано scope. Поля контактов, приватного PDF/аватара очищаются общей серверной политикой; согласие раскрывает телефон и почту только связанной компании.

`GET /api/catalog/jobs?job=ID&role=…` загружает подробности и компанию независимо от страницы; число открытых вакансий компании также считается по всей базе. `GET /api/catalog/companies?query=…` возвращает до 50 названий для фильтра, без полной выгрузки компаний.

Обычный `/api/state` содержит небольшие превью (до 20 рыночных, до 20 своих, до 20 подходящих вакансий) плюс записи, необходимые для собственной истории приглашений/откликов. Счётчики вакансий и свежих подходящих вариантов считаются SQL по всей доступной базе. Большие редактирования компании могут загрузить все её вакансии на сервер, но клиенту передаётся ограниченное превью. Добавление/снятие избранного сохраняет только изменения и проверяет доступ напрямую по базе. Фотографии проверяются SQL независимо от попадания в превью.

UI сохраняет прежние карточки/фильтры справа. Ввод ждёт 250 мс, старые запросы отменяются, пока идёт новая выдача карточки сохраняют место. Обычное фоновое обновление не включает затемнение карточек. Число кнопок страниц ограничено, тысячи номеров не создаются в DOM. Ошибки загрузки используют общий диалог, без toast.

Миграция 007 добавляет индексы по зарплате/дате, категории, связям и результату. Текущий поиск сохраняет поиск по подстроке; при значительно большем объёме и реальных замерах можно добавить pg_trgm/полнотекстовый индекс. OFFSET достаточен для текущего MVP; глубокий многомиллионный каталог потребует курсора. Отдельная история откликов/приглашений пока не пагинирована; это не рыночный каталог. Проверка локальных тысяч записей не заменяет нагрузочную проверку PostgreSQL на выбранном VPS.

## Проверка

Только отдельная QA-копия/PGlite и синтетические данные, без изменения пользовательского аккаунта. `qa/catalog-fixtures.ts` требует явно заданную остановленную QA-БД в work/portable-offerly; создаёт 2000 вакансий/2000 профилей и эталон выдачи старого алгоритма. `qa/sessions-catalog-check.mjs` проверяет сеансы, изоляцию, страницы, фильтры/ранжирование, избранное и скрытие контактов. `qa/catalog-links-check.mjs` проверяет передачу контактов после отклика, архив и медиа дальней страницы. Эти скрипты изменяют только подготовленные QA-аккаунты и не предназначены для запуска на рабочем сайте.

Итог 09.10.2026: 70 HTTP-проверок сеансов/выдачи, 16 связанных проверок контактов/архива/медиа, 54 проверки общей модели и отдельная проверка полного счётчика компании успешны. Production build и TypeScript прошли. UI: две роли, отдельное завершение сеанса, 20 карточек на странице, переход на вторые страницы и открытие подробностей проверены.
