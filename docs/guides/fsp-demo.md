# Демонстрационный ФСП ID

Реализовано 10.10.2026. Отдельный локальный OIDC-провайдер и реестр показывают полный сценарий подключения. Настоящий сервис ФСП, его пользователи и достижения не используются.

## Как попробовать

В приватной демоверсии открыть «Настройки → Аккаунт → ФСП ID» либо блок «История ФСП» в профиле кандидата. Нажать «Привязать ФСП ID · демо», выбрать тестовый аккаунт и подтвердить. На странице входа также есть «Попробовать ФСП ID · демо»: она создаёт отдельный приватный демо-аккаунт после успешного ответа провайдера.

| Аккаунт | История |
|---|---|
| Роман Крылов | Командная победа в продуктовом программировании, личное призовое место в алгоритмическом |
| Виктория Крылова | Командное участие без призового места |
| Егор Крылов | ID есть, соревнований пока нет |

После возврата доступны ID, имя тестового участника, результаты, даты, последнее обновление и кнопка обновления. «Выбрать другой тестовый аккаунт» запускает новую подтверждённую привязку. Отмена сохраняет прежнюю привязку. Пароль ФСП не запрашивается.

«Посмотреть карточку работодателя» переключает роль и открывает выбранный демо-профиль в категории Backend Middle. Достижения зеркалируются в один из трёх уже существующих синтетических профилей приватного каталога, чтобы показать сценарий с обеих сторон без публикации кандидата на обычном рынке. Профессиональный грейд, индекс и технологии этих профилей сохраняются. Это демонстрационная обвязка, а не модель владения профилями реальных людей.

## Запуск

Из `offerly-web` с установленными существующими зависимостями:

```text
npm run dev:with-fsp
```

Команда компилирует прежний assessment engine и запускает сайт на порту APP_URL и провайдер на `http://127.0.0.1:5291`. Остановка команды завершает дочерние процессы. Отдельный запуск провайдера: `npm run dev:fsp`; обычный `npm run dev` запускает только сайт.

В текущем npm node_modules не запускать pnpm с автоустановкой поверх исходного lockfile. Новых production-зависимостей нет; провайдер использует Node HTTP/crypto, клиент — существующий openid-client.

Настройки по умолчанию: ENABLE_DEMO=true, development, локальный APP_URL, FSP_DEMO_ISSUER=`http://127.0.0.1:5291/realms/fsp-demo`, FSP_DEMO_CLIENT_ID=`offerly-demo`, FSP_DEMO_CLIENT_SECRET=`local-demo-only`. Последний параметр — известное значение только для локального стенда, не production credential. Переопределённые параметры клиента должны совпадать у сайта и провайдера. `FSP_DEMO_ENABLED=false` выключает функции сайта. Провайдер слушает только loopback; production и внешние origins отвергаются. Для развёрнутого стенда потребуется отдельный изолированный тестовый провайдер с HTTPS и собственной конфигурацией; этот локальный сервис не публиковать как настоящую ФСП.

## Обмен и хранение

Привязка проходит Authorization Code + PKCE S256, random state/nonce, browser cookie, проверку подписи RS256, issuer/audience/expiry. Одноразовый code живёт одну минуту; browser-bound flow — десять. Вход/привязка к существующей демоверсии привязаны также к исходной локальной сессии. Повторное применение callback, подмена браузера или кода отвергаются. Отдельная страница провайдера имеет выбор аккаунта, подтверждение/отмену и обратную связь во время отправки.

Миграция012 создаёт отдельные fsp_demo_flows/fsp_demo_links. Реальные external_identities и параметры FSP_OIDC_* не изменены. После проверки ID Token сервер запрашивает демонстрационный реестр через клиентскую аутентификацию, проверяет согласованную структуру синтетического набора и сохраняет только публичные события/статус. Токены не сохраняются. Ни вход, ни реестр не присваивают грейд и не подтверждают технологии.

Состояния: synced, empty, unavailable. Успешная пустая история очищает прежние события выбранного профиля. Сбой сохраняет последние результаты того же ID и дату успешной синхронизации; результаты другого ID при переключении не переименовываются в новые. Блокировка привязки перед записью отвергает запоздалый результат старого запроса. Source всех событий — demo. В ранжировании используются существующие правила результата/релевантности; ID без результатов бонуса не даёт. В карточке работодателя показаны источник, время обновления и сохранённая история при сбое.

## API

| Метод | Ручка | Назначение |
|---|---|---|
| GET | /api/identity/fsp-demo | Доступность стенда и собственная приватная привязка |
| POST | /api/identity/fsp-demo/start | intent=login/link, role=candidate/employer → authorizationUrl |
| GET | /api/identity/fsp-demo/callback | Проверка одноразового ответа, привязка, импорт, фиксированный redirect |
| POST | /api/identity/fsp-demo/sync | Обновление только собственных демонстрационных результатов |

Мутации требуют Origin приложения. Привязка/синхронизация без входа401; в обычном аккаунте403; изменение привязки во время синхронизации409; выключенная демонстрация503. Callback не принимает произвольный return URL. Вход с обычной сессией не заменяет её демо-сессией молча. Callback query не пишется в стандартный access log; диагностика содержит лишь имя/код ошибки.

## Проверка

`qa/fsp-demo-check.mjs` —73 HTTP-проверки: настоящий OIDC-обмен, JSON/redirect ответ провайдера, три истории, отмена, повтор, чужой браузер, подложный code, Origin, приватные scope, отсутствие изменения грейда/технологий, ошибка и повторная синхронизация, отсутствие событий на обычном рынке и запрет перезаписать привязку старым вводом ID. Отчёт `qa/results/latest/fsp-demo-results.json`.

Дополнительно прошли57 прежних проверок реального OIDC-клиента на отдельном протокольном fixture,54 общеплатформенных,63 сценария работодателя,19 unit ранжирования/защиты дат. TypeScript, production build, ESLint новых файлов успешны. Новая модель не изменяла engine и package-lock. Записывающие проверки выполнялись в отдельном PGlite `.data/fsp-demo-qa/postgres`. До запуска основной базы сохранена копия `.data/backups/before-fsp-demo-20261010`.

В браузере проверены выбор и возврат, два загруженных события, переход в карточку работодателя и смена на аккаунт без истории. Это проверка демонстрационного сценария, не реальная интеграция ФСП и не человеческая проверка квалификации.
