# MCP работодателя: синтетический локальный стенд

Реализован согласованный scope: `search_candidates`, `get_candidate_profile`, `draft_invitation`. Поиск и рейтинг используют `searchCatalog` и существующую SQL-политику employer-2. Отдельные аудит, роли агента, OAuth, расписание и сроки токенов не добавлены. MCP не выполняет решения о найме и не отправляет сообщения или приглашения.

## Кабинет

Настройки работодателя → **MCP · агент**: состояние сервера, SSE URL, копирование адреса, создание/копирование API-токена, конфигурация `claude_desktop_config.json`. Замена токена закрывает соединения и отзывает старый токен; отключение удаляет действующее разрешение. Токен не попадает в `/api/state`, localStorage или журналы. В базе хранится SHA-256 для аутентификации и AES-256-GCM ciphertext для явного повторного копирования владельцем.

Приглашения → **Черновики приглашений**: текст и зарплатная вилка видны до отправки. «Одобрить и отправить» одним нажатием отправляет предложение от компании. «Удалить черновик» переводит его в удалённый статус. Только собственная browser cookie и точный Origin допускаются к этому API; Bearer агента не является подтверждением HR. Повтор одобрения уже отправленного черновика не создаёт второе приглашение. Если кандидат скрыл профиль или отозвал согласие, одобрение отклоняется. После отправки действуют прежние правила согласия на чат.

## Транспорт и подключение

MCP реализован внутри существующего Next.js/Node backend, без Python/FastMCP и без новых production dependencies. Использованы JSON-RPC и SSE. Поддерживаемые версии: 2024-11-05, 2025-03-26, 2025-06-18, 2025-11-25. Новый протокол 2026-07-28 не заявлен; неизвестный version header отклоняется. Методы: initialize, ping, tools/list, tools/call; приняты notifications/initialized и notifications/cancelled. Инструменты выполняются синхронно; отмена выполняющегося инструмента не реализована.

- `GET /api/mcp/sse`: `Accept: text/event-stream`, `Authorization: Bearer …`.
- Первый SSE `endpoint` указывает `/api/mcp/messages?sessionId=…`.
- `POST` к этому адресу с тем же Bearer принимает один JSON-RPC запрос. Ответ приходит событием `message` в исходный SSE поток.
- Дополнительный `POST /api/mcp` возвращает JSON напрямую. SSE listen через GET на нём не поддерживается (405).
- Foreign Origin запрещён. Без Origin native-клиент допускается только с действующим Bearer. Cookie браузера не заменяет токен агента. Bearer в query string не принимается.

`scripts/mcp-stdio.mjs` — локальный мост stdio↔SSE для desktop-клиентов. Он использует Node.js 22+, не устанавливает пакеты, не запускает браузер, не обращается к внешним хостам. Разрешены только loopback адреса; сведения и токен не выводятся в stderr. Конфигурация в UI содержит реальный путь к файлу и URL. При Docker путь к скрипту должен быть путём **на компьютере клиента**, а не `/app` внутри контейнера; его можно поправить в окне конфигурации или задать `MCP_STDIO_SCRIPT_PATH`.

Конфигурация Claude Desktop предоставлена для совместимости с MCP, а не как доказательство автономности модели. Само desktop-приложение может использовать облачную модель. Для автономного демонстрационного контура нужен локальный MCP-клиент с локальной моделью; модель/оркестратор в scope этой реализации не входят. Бэкенд и мост сами не вызывают LLM.

## Инструменты

```json
{"name":"search_candidates","arguments":{"specialty":"Backend","grade":"Middle","skills":["Python"],"priority":"balanced","page":1}}
```

Необязательные фильтры: направление, уровень, технологии, verifiedOnly, нижний/верхний бюджет, формат, приоритет balanced/test/fsp и страница 1–100. Размер страницы 20. verifiedOnly ищет только проверенные технологии, по умолчанию учитываются также заявленные навыки при фильтрации. Ответ не превращает заявленный навык в подтверждённый. COUNT и пагинация считаются после исключения реальных аккаунтов, собственных/скрытых/неполных/удалённых/приостановленных профилей и профилей без согласия.

```json
{"name":"get_candidate_profile","arguments":{"candidateId":123}}
```

Ответ: ID, направление, подтверждённый или заявленный грейд, verifiedTechnologies, результат теста/версия/источник симуляции, агрегированный статус ФСП и компоненты рейтинга. Без ФИО, телефона, email, города, биографии, проектов, трудовой истории, файлов, названий соревнований, внешних ссылок и переписки. Прямой доступ по ID заново проверяет доступность и scope.

```json
{"name":"draft_invitation","arguments":{"candidateId":123,"title":"Backend в команду платформы","description":"Предлагаем обсудить разработку сервиса и условия сотрудничества.","salaryMin":180000,"salaryMax":230000,"requestId":"invitation-draft-001"}}
```

Обе границы месячной зарплаты обязательны, положительные целые рубли до 10 млн, max≥min. Без вилки возвращается ошибка правил платформы. requestId обеспечивает идемпотентность: одинаковый запрос возвращает тот же ID; изменение содержимого с прежним requestId — конфликт. Неизвестные поля, произвольный SQL и инструменты отправки отвергаются. Данные профиля не являются инструкциями для агента; интерфейс не выдаёт произвольный текст резюме.

## Docker Compose: локальная изоляция

В приватной `.env` задать POSTGRES_PASSWORD и MCP_TOKEN_ENCRYPTION_KEY (64 hex символа). Ключ можно сгенерировать командой `node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"`; хранить вне Git. APP_URL для base-compose должен быть задан, например http://localhost:3000. Настроечный ключ не является токеном работодателя.

```powershell
docker compose -f compose.yml -f compose.mcp-demo.yml config --quiet
docker compose -f compose.yml -f compose.mcp-demo.yml up -d --build
```

Overlay включает демонстрацию и MCP и помещает DB/migrate/app во внутреннюю сеть `mcp-local` без исходящего доступа. Node gateway публикует сайт только на loopback-порту3000: он соединён с `mcp-local` и отдельной ingress-сетью, проксирует только фиксированный `app:3000`, не умеет CONNECT/upgrade и не принимает адрес внешнего сервера. Это позволяет открыть сайт на Docker Desktop, где публикация порта контейнера только во внутренней сети не работает. Сам gateway технически имеет ingress-сеть; backend и DB к ней не подключены. Его код не вызывает внешние службы. Новых пакетов/образов для прокси нет. Требуется Docker Compose с поддержкой `!reset` (2.24.4+).

Перед применением к существующему стенду проверить итоговый `docker compose config`; команда может содержать приватные environment значения, её вывод не публиковать. Миграция014 применяется штатным migrate-сервисом. Контейнеры не запускают отдельную модель.

Обычный compose имеет MCP_DEMO_ENABLED=false. Для production-сборки обязательный приватный ключ предотвращает хранение токенов с автоматически созданным ключом. Dev использует отдельный некоммитящийся `.data/mcp-token.key`. При смене ключа нужно заменить API-токены; потеря ключа не раскрывает токены, но отключает их повторное копирование.

## Безопасность и 152-ФЗ

Эта версия не открывает доступ к реальным кандидатам: и владелец токена, и профили должны иметь серверный `users.demo=true`, кандидат принадлежать тому же scope, сохранять видимость/согласие и заполненность. «ru mode» и переключатель открытия реальных данных отсутствуют. Поля нельзя расширить параметрами инструмента. Генераторы демо создают вымышленные профили; импорт реальных резюме в демонстрационные аккаунты нельзя считать разрешением на передачу через MCP.

Нельзя утверждать, что удаление ФИО делает профессиональные данные юридически обезличенными: связанный с человеком ID, грейд и достижения могут оставаться персональными данными. Поэтому текущая граница — синтетические данные, а не обещание обезличивания любых реальных записей. Перед подключением реальных людей отдельно определить цели/основание/согласия, операторов и обработчиков, хранение в РФ, документы и уведомления, права субъекта, защиту ИСПДн и резервные копии. Сам MCP и локальная БД не подтверждают соблюдение всего закона. Требования локализации и автоматизированных решений следует сверять по актуальной редакции закона, а не по настройкам интерфейса.

Источники: [152-ФЗ, актуальная редакция](https://www.consultant.ru/document/cons_doc_LAW_61801/), [статья16 об исключительно автоматизированных решениях](https://www.consultant.ru/document/cons_doc_LAW_61801/22e884a41450dcb5cb62d956583ad32abe2bbbe9/), [23-ФЗ от28.02.2025](https://publication.pravo.gov.ru/document/0001202502280034), [портал РКН](https://pd.rkn.gov.ru/), [SSE/Streamable HTTP MCP](https://modelcontextprotocol.io/specification/2025-11-25/basic/transports).

Технические меры: шифрование копируемого токена, его отзыв/замена, серверное членство компании, exact Origin, лимиты тела/частоты, закрытый allowlist инструментов/полей, изоляция scope и неизменённые правила согласия на общение. Удаление аккаунта удаляет его MCP-токен и связанные черновики. Прямое автоматическое кадровое решение не реализовано.

## Проверка

Изолированная база `.data/mcp-qa/postgres`, сервер5174 и отдельный `.next-mcp-qa`; основная база для QA не открывается. При остановленном QA-сервере:

```powershell
$env:PGLITE_PATH='.data/mcp-qa/postgres'
node node_modules/tsx/dist/cli.mjs qa/seed-mcp-qa.mts
node qa/mcp-server.mjs
```

В другом терминале `node qa/mcp-check.mjs`. Проверяются настоящий stdio/SSE, три инструмента, отсутствие закрытых полей, исключение real/hidden/paused/incomplete/deleted, scope, обязательная зарплата, повтор операции, Browser-only approval, недоступный кандидат, отзыв/замена токена. Результат `qa/results/latest/mcp-results.json` не содержит токенов/текстов профилей. Состояние ключей и cookie фикстур — только в `.data`.

Docker smoke-test: поднимать отдельный compose-проект `offerly-mcp-qa`, затем `$env:MCP_DOCKER_QA='1'; node qa/mcp-docker-check.mjs`. Проверка создаёт новый синтетический demo workspace на localhost:3000, проверяет поиск/профиль/вилку, настоящий SSE и отправку после HR approval на PostgreSQL; в конце отзывает тестовый MCP-токен. Основной dev-сайт5173 не изменяется. Приватный env стенда хранить в `.data`, не коммитить.
