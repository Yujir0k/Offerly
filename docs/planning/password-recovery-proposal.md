# Предложение: восстановление пароля

Статус: сценарий для согласования, ещё не реализован.

1. На странице входа небольшая ссылка «Забыли пароль?» рядом с полем пароля.
2. Экран в существующем тёмном стиле: email и «Отправить код». Ответ одинаковый для существующего и неизвестного адреса: «Если аккаунт с такой почтой существует, мы отправили код». Адрес не раскрывает наличие аккаунта.
3. Шесть существующих округлых ячеек, 10 минут, вставка целого кода, красное состояние ошибки; повторная отправка с ограничением частоты. Заполненный код проверяется отдельным назначением reset-password, несовместимым с подтверждением/сменой почты. В разработке письмо видно в Mailpit.
4. После правильного кода — два поля «Новый пароль» и «Повторите пароль», оба с глазиком. Требования те же: 12–128 символов. Код обменивается на короткоживущее одноразовое разрешение сброса; до его проверки пароль и сеансы не меняются.
5. Успех в фирменном стиле и кнопка «Перейти ко входу». Автоматического входа нет. Смена пароля отзывает все сеансы Офферли, включая текущий, и отправляет уведомление на почту без пароля.

Коды/разрешения генерируются криптографически, в БД только хеши, срок и счётчик попыток; ограничения по адресу/источнику, одноразовость и атомарное использование. Не переносить dev-код в production. Ошибки — общий минималистичный диалог с blur, специальные состояния кода — уже существующие экраны.

Если доступа к почте нет, предложить вход через ранее привязанный ФСП ID. Сброс местного пароля не должен обходить ФСП или автоматически добавлять пароль аккаунту, у которого его нет: для ФСП-only восстановление у провайдера. Автоматическая смена адреса без доказательства владения недопустима; ручной канал поддержки можно определить позже.

Ориентир: [OWASP Forgot Password Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Forgot_Password_Cheat_Sheet.html). Это проектное предложение, не реализованная функция.
